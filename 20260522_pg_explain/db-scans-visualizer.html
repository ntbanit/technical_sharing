Bitmap Index Scan

Key Insight

1
Build Bitmaps from Indexes

Each index is scanned; a bit is set for every page that has at least one matching row. No heap access yet.

2
Combine with AND / OR

Multiple bitmaps are AND-ed (both conditions) or OR-ed (either condition) in memory — very cheap, no I/O.

3
Hand off to Bitmap Heap Scan

The resulting bitmap is used by the heap scan in the next step to read only the marked pages.

Advantages
  • Combine multiple indexes
  • Turns random I/O → sequential
  • No duplicate heap fetches
Trade-offs
  • Memory for bitmap
  • Recheck needed (lossy)
  • Not for ORDER BY

Bitmap Heap Scan

Uses the bitmap produced by the Bitmap Index Scan to visit only the marked heap pages, in physical order — converting what would be random I/O into sequential I/O.

Each page may be "lossy" (bit covers a whole page). The planner rechecks the filter on each row in the page.

Scan Type Comparison

How the planner picks between scan strategies based on selectivity, table size, and available indexes.

DECISION MATRIX

Scan Type I/O Pattern Index Used Multi-Index Best Selectivity ORDER BY Cost (many matches)
Sequential Scan Sequential No No > 20–30% Needs sort Stable O(N)
Index Scan Random Yes (B-tree) One only < 5–10% Free if ordered Random I/O storm
Bitmap Index Scan In-memory Yes Yes (AND/OR) 5–20% Not guaranteed Avoids dups
Bitmap Heap Scan Sequential Via bitmap Yes 5–20% Needs sort Skips pages

WHEN DOES THE PLANNER CHOOSE EACH?

Seq
Use Sequential Scan when…

No usable index exists, table is small, or >~25% of rows match — reading everything is cheaper than index overhead.

Idx
Use Index Scan when…

Very few rows match (<5%), table is large, and data is cached in memory (so random I/O is cheap).

Bmp
Use Bitmap Scan when…

Moderate selectivity (5–20%), or query needs to combine two or more indexes with AND/OR conditions efficiently.

Heap
Bitmap Heap Scan always pairs with Bitmap Index Scan

It is the second phase: it consumes the bitmap to do bulk sequential reads of only the relevant pages.
